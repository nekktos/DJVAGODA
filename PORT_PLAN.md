# Перенос «ДжваГоды» на Unity

**Решение автора от 30.09.2026:** переносим игру с Godot 4.7.2 на Unity —
«всё и сразу», без пробного среза. Причины — все сразу: графика и ассеты, сеть
и Steam, команда и карьера, производительность.

**Ассеты не переносим** (ответ автора): модели, текстуры и звуки делаются в
Unity с нуля. До этого — серые заглушки из примитивов. Выбор и покупку ассетов в
Asset Store делает автор: нужен вход в его аккаунт.

**С Unity работаем через MCP** (ответ автора): редактор ведётся инструментами
MCP-моста, а не правкой файлов сцен руками.

**Godot-версия остаётся в репозитории** (`godot_project/`) как эталон
поведения, пока Unity-версия её не догонит. Все числа баланса, правила и
находки живых playtest'ов и «долгих партий» — там, в коде и комментариях.

## Что нужно от автора

1. **Unity Hub** (unity.com/download) и вход в аккаунт — лицензия Personal.
2. В Hub — **Unity 6 LTS** (6000.0.x) с модулями **Windows Build Support** и
   **Mac Build Support (Mono)**.
3. Сказать, когда установлено: дальше проект, MCP-мост и сборки — моя часть.

## Устройство

```
unity_project/                 Unity-проект
  Assets/DjvaGoda/
    Core/                      ПРАВИЛА ИГРЫ на чистом C#, без UnityEngine
      DjvaGoda.Core.asmdef     noEngineReferences: true
      Economy/ Combat/ Units/  ресурсы, постройки, ступени, лавки, оружие,
                               заклинания, строи, шахты…
    Game/                      Unity-слой: сцены, сеть, физика, навигация, UI
    Tests/EditMode/            проверки ядра (без сцены), Tests/PlayMode/ — сцены
godot_project/                 эталон: прежняя версия
```

**Ядро — на C# 9**, как весь проект. Сперва его держали в подмножестве C# 5,
чтобы проверять системным `csc` без редактора; теперь редактор открыт всегда
и ведётся через MCP, и проверки ядра — EditMode-набор Unity Test Framework
(`Tests/EditMode/CoreTests.cs`, доли секунды). Без редактора — `./unity_tests.sh EditMode`.

**Оси.** Ядро живёт в осях Unity: «вперёд» — +Z, «вправо» — +X, yaw в
радианах растёт вправо (угол Y в `Quaternion.Euler`). `CoreSpace` только
переводит типы, без отражений. До 01.10.2026 ядро жило в осях Godot-версии
(«вперёд» — −Z) с отражением z на границе; перевели отражением всех данных и
формул — мир в Unity не сдвинулся ни на миллиметр (сверено снимком старого
ядра: план, рельеф, лес, точки, повороты, строй, прицел, движение). Сравнивая
числа с Godot-версией, помнить: z и yaw там — с обратным знаком.

**Решения по технологиям** (перенос устройства Godot-версии):

| Godot-версия | Unity |
|---|---|
| High-Level Multiplayer, «хост считает всё, клиент — своё движение» | Netcode for GameObjects + Unity Transport, та же модель прав |
| `@rpc` с проверкой отправителя | `ServerRpc`/`ClientRpc` (Rpc с SendTo) с проверкой отправителя |
| MultiplayerSynchronizer | движение — `NetworkTransform` с правом владельца (AuthorityMode Owner); прочее — `NetworkVariable` |
| MultiplayerSpawner | `NetworkObject` + спавн с сервера |
| сетка навигации с перепечкой в потоке | AI Navigation: `NavMeshSurface` запечена в редакторе, постройки — `NavMeshObstacle` с вырезанием |
| мир строится при запуске | неподвижный мир собран в редакторе и лежит в сцене («ДжваГода → Собрать мир»); деревья — процедурные (`TreeShapes`), сажаются при загрузке |
| наборы `tools/*_test.gd` + `run_tests.sh` | Unity Test Framework: ядро — EditMode, сцена — PlayMode; через MCP или из командной строки |
| `build_playtest.ps1` | сборка из командной строки редактора (`-batchmode -executeMethod`) |
| Steam — нет | Steamworks (Facepunch) — после паритета |

## Порядок работ

Каждый шаг — с проверками и коммитом, как раньше.

1. ✅ **Ядро правил** (EditMode `CoreTests`, 182 проверки):
   - ресурсы и цены, постройки и ступени, стороны и вражда, правило
     снаряжённости стражи, оружие, заклинания, строи;
   - шахта с копателями, казна (при себе и склад), постройка (стройка, поле,
     ступени, урон), обоз (скорость, перехват, грабёж, полный склад), голод;
   - тело и ранения, здоровье, выносливость, мана, прокачка;
   - исход партии (захват дворца, выбывание, победа), приказы и задания;
   - решения распорядителя ИИ; числа бойцов, батраков и ИИ;
   - раскладка карты; раскладка клавиш; сделки (лавка, кузня, стройка,
     укрепление, наём, конюшня, обоз);
   - формулы урона, заклинания с кастом и окном неуязвимости, куча добычи,
     схема сохранения;
   - рельеф, правила постановки построек;
   - мозги ИИ: военный отряд, герой, батрак, боец; рейс обоза; возрождение;
     пост распорядителя; места в сессии;
   - лес, план мира из примитивов, свой генератор случайных чисел;
   - движение персонажа, полёт снарядов и прицел, дуга удара, действие
     заклинаний, верстак и перевязка.
2. ⏳ **Установка Unity** — автор. Затем: проект, пакеты (Netcode, Transport,
   AI Navigation, Input System, Test Framework, URP), MCP-мост.
3. **Сеть и персонаж:** хост/подключение по IP, спавн, движение (считает
   клиент), камера из-за плеча и первое лицо, прыжок, бег, выносливость.
   ⏳ Движение — в ядре (`CharacterMotor`); персонаж, камера, ввод и
   загрузчик сцены написаны (`Game/Characters`, `Game/Input`, `Bootstrap`).
   Сеть: сессия (хост/IP, одобрение с местами по `Lobby`) и сетевая половина
   персонажа (`Game/Net`) написаны. Через MCP собраны сцена
   `Scenes/Main.unity` (загрузчик в сетевом режиме, NetworkManager с
   транспортом, `NetSession` + меню `NetMenu`) и префаб `Prefabs/Player.prefab`
   (NetworkObject, в списке сетевых префабов). Хост в Play проверен: персонаж
   на точке стороны, ходит, положение уходит в сеть. Ключи для прогонов без
   мыши: `-host [порт]`, `-join адрес [порт]`, `-side 0|1|2`; порт 24545.
   Проверено вдвоём: хост в Play редактора + отладочная сборка
   (`build/unity_dev`) с `-join 127.0.0.1 -side 1` — клиент одобрен, эльф на
   своей точке (место 1), положение пишет клиент, исключений нет.
4. **Бой:** оружие, зоны попадания, здоровье, снаряды, заклинания, мана.
5. **Мир:** карта (зоны, плато с пандусом, форт, дворец, лес, шахты) —
   серыми примитивами. ⏳ План мира — в ядре (`WorldPlan`, проверки). Карта
   одна на все партии (семена плана — константы), поэтому неподвижная часть
   собирается в редакторе пунктом «ДжваГода → Собрать мир»
   (`Editor/WorldBake.cs`) и хранится в сцене `Main`: меши и материалы —
   файлами в `World/Generated`, сетка навигации запечена. Пункт ничего не
   трогает, если план не менялся («Собрать мир заново» — насильно). Деревья
   (1700 леса и рощи плана) в сцене не хранятся: `World` сажает их при
   загрузке процедурными мешами `TreeShapes` (ели и лиственные, по 8
   вариантов, low-poly), в редакторе — без сохранения в сцену. Проверка
   `WorldMatchesPlan` ловит мир, не пересобранный после правки плана.
6. **Экономика:** казна стороны, склад, постройки со стройкой и ступенями,
   батраки, обозы, шахты, лавки, кузня, голод.
7. **ИИ:** гарнизон, отряд, распорядитель, вожак; навигация.
   ⏳ Мозги — в ядре; в Unity написаны сетка навигации (`NavWorld`, встроенный
   API), участники мира (`Game/Actors`: боец, постройка, обоз, отряд ИИ).
8. **Ранения:** зоны на костях, отрыв и перебитые конечности, протезы.
9. **Цели партии:** захват дворца, выбывание сторон, командир и приказы,
   старейшина и задания, сохранения.
10. **Интерфейс:** HUD картинками, панель команд, окна построек и лавки,
    переназначаемые клавиши, обучение.
11. **Долгие партии** на Unity-версии — паритет по звеньям цепочки злодея.
12. **Сборка для тестеров** Windows и macOS.
13. **Ассеты** — по выбору автора, на место заглушек.

## Отличия от Godot-версии, найденные при переносе

Проверки ядра гоняют правила в чистом виде и находят то, что в Godot-версии
не всплывало. Каждое отличие — осознанное, с объяснением в коде:

- **Рельеф:** растушёвки плоских мест шире (не меньше 80 м). Свой шум доходит
  до ±1, и при прежних полосах у дорог выходил уклон 39° при потолке
  навигации 45°; теперь худший ~25°.
- **Герой ИИ:** запрет стрелять вплотную — только для огненного шара, а не для
  любого дальнобойного (эльф с луком стрелял бы в упор).
- **Обоз:** в лоб на стену (дом прямо на линии маршрута) толчок объезда ровно
  против курса, и обоз качался у стены вечно. Теперь скользит вдоль стены и
  помнит сторону обхода до следующей точки.

- **Некротический протез:** Godot-версия проверяла запас трофеев на каждую
  конечность отдельно (не меньше 10), а списывала по 10 за каждую. С двумя
  оторванными ногами и 15 трофеями проверка проходила, и трофеев становилось
  −5. Здесь цена считается за все конечности сразу.
- **Шейдер заглушек в сборке:** `Shader.Find("Universal Render Pipeline/Lit")`
  в редакторе находит шейдер, а в сборке возвращает null — шейдер без
  ссылающихся материалов вырезается. Мир не строился. Палитра теперь копирует
  образец `Resources/Stub.mat`.
- **Одобрение подключения** должно быть включено и у клиента: оно входит в
  сверяемый NetworkConfig, иначе хост сбрасывает клиента («NetworkConfig
  mismatch»).
- **Лучник-боец** в ядре сперва бил как мечник (22 урона, откат 1.1 с); в
  Godot-версии он бьёт стрелой лука (30, 1.0 с). Исправлено.

## Подключение MCP-моста

1. ✅ `uv` поставлен (`python -m pip install --user uv`), лежит в
   `%APPDATA%\Python\Python314\Scripts` — путь добавить в PATH сессии.
2. В проект — пакет по git-адресу (в `Packages/manifest.json`):
   `"com.coplaydev.unity-mcp": "https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main"`.
3. В редакторе: **Window → MCP for Unity** — мастер проверит Python и uv;
   сервер слушает `http://localhost:8080/mcp`, в панели должно быть `Connected`.
4. Claude Code: `claude mcp add --transport http unityMCP http://localhost:8080/mcp`
   (или «Configure All Detected Clients» в окне моста).
5. Проверка: создать в пустой сцене три куба — и удалить.
